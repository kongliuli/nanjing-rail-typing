## 二、调研要点：该抄什么、不该抄什么

**应借鉴**
1. 「打错不前进」引擎（nothing-to-backspace）：错键不消耗进度也不需退格，重打即可——比"宽容判定+退格"更优雅，也是 typing 社区共识的练习友好模型（forgiving mode + 即时逐键反馈）。
2. Net WPM 标准公式：Net = Gross − 未修正错误数/分钟；区分已修正/未修正错误。我们目前只算 Gross 和粗准确率，成绩不可比。
3. 盖章本成就 + 每模式独立排行榜（localStorage 即可）。
4. 从个人历史重建「错题重练」（对应其 Weakness drill）。

**不必跟风**：3D 站牌/列车皮肤、博客内容生态、键盘测试器等泛工具站（对方成规模运营的产物，现阶段跟是浪费弹药）。

**关键洞察**：对方用一套引擎吃下 4 城市，说明**数据驱动的城市内容包架构**才是可扩展核心。我们补 6 条线、未来加苏州/上海的过程，就是把这个架构显式化的最佳时机。

- ~~补齐南京 **5 / 6 / 7 / S2 / S4 / S6 / S9**~~ → 实际收录 5/7/S2/S4（滁州段）/S6/S9 共 6 线 102 站（6 号线未开通，按「仅收录已开通」政策排除）；合计 15 线 / 293 线路站 / 去重 259 站。
- 站序/英文名：维基线路页（子代理抓取，S2/S4/S6/S9 标识色取自官方色值模块）✅
- 坐标：Overpass 通道 ✅（100 精确匹配 + 2 插值）
- 站故事：全部双语（zh/en）✅，换乘站文案标注换乘关系 ✅
- 上线部署（GitHub Pages）：**用户拍板不做**，维持纯本地。

### P2 · 游戏体验追平（~1-2 个工作日当量）
1. **盖章本**：每通线一枚线路色印章 + 集齐进度墙（纯 localStorage）。
2. **引擎改造**：错键不前进、退格可选；成绩页区分已修正/未修正错误，输出标准 Net WPM。
3. **逐站 split 表** + 「重练最慢 3 站」按钮。
4. **错题本**：音节级错误统计，攒够自动生成针对性练习（Weakness drill 同款）。
5. **音效**：按键声、进站「叮咚」门铃（南京地铁同款旋律的免费替代）、终到提示；可静音开关。

### P3 · 深挖差异化（~2-3 个工作日当量）
1. **汉字模式**：接 IME composition 输入汉字站名（对方 kanji 模式同款；我们 beforeinput 已处理 insertCompositionText，基础在）。
2. **PWA**：manifest + Service Worker，手机加到主屏、离线可玩（零依赖架构改造成本极低）。
3. **地图升级**：滚轮/双指缩放 + 拖动；可选 Leaflet+高德/OSM 瓦片街底图（需联网，做成开关）。
4. 方言读音彩蛋（南京话站名播报）、青奥/马拉松等主题列车皮肤。

### P4 · 平台化（按需）
1. **城市包架构**：`data.js` → `data/nanjing.js` + 运行时注册，新城市一份文件即可接入；顺带出苏州（1 条线试水）/上海。
2. **部署**：GitHub Pages 免费零运维（你已有 GitHub 台账）；绑定自定义域名可选。
3. **分享对战**：先做 Replay 对战（双方各自本地计时、互发回放校验），规避实时后端；真排行榜再考虑 Cloudflare Workers + KV。
4. 线路 guide 静态页（换乘笔记、易错音节 top10）。

## 四、移动端专项打磨清单（并入 P2/P3）
- 软键盘唤起后视口跳动：加 `interactive-widget=resizes-content` 观察兼容性；
- 气泡与列车在长线路（1/3 号线 30+ 站）小屏上拥挤：气泡折叠为「📜」角标点开；
- 加「分享到微信」的 canvas 海报图（站数/用时/印章）；
- iOS Safari 长按输入框呼出放大镜的规避（`-webkit-user-select: none` 于非输入区）。

## 五、待拍板的取舍
1. **上线形态**：纯本地静态页 vs GitHub Pages vs 带后端（排行榜/云同步/真对战需要后端；建议维持本地优先，Pages 发布）。
2. **站故事语言**：是否随 P1 一起做双语（建议是）。
3. **引擎改造时机**：「错键不前进」会改变手感并使旧纪录不可比——建议作为 v2.0 一次性切换并保留旧纪录标记。
